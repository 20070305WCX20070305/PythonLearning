## 正文

### 2.1 地址与指针

内存像一排编号的抽屉，编号就是**地址**。**指针就是一个保存地址的变量**。

```c
#include <stdio.h>
int main(void)
{
    int x = 42;
    int *p = &x;              /* &x 取得 x 的地址，p 指向 x */

    printf("x 的值       = %d\n", x);
    printf("x 的地址     = %p\n", (void *)&x);
    printf("p 保存的地址 = %p\n", (void *)p);
    printf("*p 解引用    = %d\n", *p);      /* * 跟着指针，取它指向的值 */

    *p = 100;                 /* 通过指针修改变量 */
    printf("修改后 x     = %d\n", x);
    return 0;
}
```

预期输出（地址每次运行都不同）：两个地址相同，`*p 解引用 = 42`，`修改后 x = 100`。

要点：`int *p` 读作「p 是指向 int 的指针」；`p` 里存地址，`*p` 是那个地址上的 int；指针类型决定「解引用读几个字节」和「加 1 走多远」。空指针 `NULL` 表示不指向任何东西。

常见错误：

- 声明后未初始化就解引用：`int *p; *p = 5;`，行为未定义。
- 忘记 `&`：`scanf("%d", x)` 少了取地址符，运行时崩溃。
- 打印地址用 `%p` 且应转成 `(void *)`；用 `%d` 打印指针是错的。

### 2.2 指针与数组

数组名在多数表达式里会**退化**成「首元素地址」，但数组本身和指针并不完全一样。

```c
#include <stdio.h>
int main(void)
{
    int a[5] = {10, 20, 30, 40, 50};
    int *p = a;                  /* 等价于 int *p = &a[0]; */

    printf("a[2]=%d, *(a+2)=%d, p[2]=%d\n", a[2], *(a + 2), p[2]);
    printf("sizeof(a)=%zu, sizeof(p)=%zu\n", sizeof(a), sizeof(p));

    p++;                         /* 指针加 1 = 前进一个 int（4 字节） */
    printf("p 指向 = %d, p - a = %ld\n", *p, (long)(p - a));

    for (int *q = a; q < a + 5; q++)          /* 用指针遍历数组 */
        printf("%d ", *q);
    printf("\n");
    return 0;
}
```

预期输出（WSL2 x86_64）：

```
a[2]=30, *(a+2)=30, p[2]=30
sizeof(a)=20, sizeof(p)=8
p 指向 = 20, p - a = 1
10 20 30 40 50
```

要点：`a[i]` 完全等价于 `*(a + i)`；数组名不能被赋值（`a = p;` 非法）。函数参数写成 `int a[]` 时实际是指针，`sizeof` 得 8，所以长度必须单独传参。

常见错误：

- 越界访问：`a[5]`、`*(a + 5)` 都是错的，编译器不检查，ASan 会报。
- 以为 `sizeof(a)/sizeof(a[0])` 在函数内可用：参数是指针，算出来通常是 2。
- `p + n` 超出数组范围后再解引用，或两个无关指针相减。

### 2.3 字符串与指针

```c
#include <stdio.h>
int main(void)
{
    const char *msg = "hello";       /* 只读，不要改 */
    const char *p = msg;

    while (*p != '\0') {             /* 逐个字符访问，直到结尾 */
        putchar(*p);
        p++;
    }
    putchar('\n');
    printf("第 2 个字符 = %c\n", *(msg + 1));
    printf("从 e 开始的子串 = %s\n", msg + 1);   /* %s 接收 char* */
    return 0;
}
```

预期输出：`hello`、`第 2 个字符 = e`、`从 e 开始的子串 = ello`。

常见错误：

- 把 `char *` 指向字面量后试图修改（崩溃或静默失败）；要修改就用 `char buf[] = "hello";`。
- 用 `==` 比较字符串（比较的是地址），要用 `strcmp`。
- `printf("%s", p)` 的 p 不是以 `'\0'` 结尾的 `char *`，会一直打印垃圾。

### 2.4 函数参数传址与 const

C 的参数是值传递：想修改调用者的变量，就把地址传进去。

```c
#include <stdio.h>

static void swap(int *a, int *b)      /* 接收两个地址 */
{
    int t = *a;
    *a = *b;
    *b = t;
}

int main(void)
{
    int x = 3, y = 7;
    swap(&x, &y);
    printf("x=%d, y=%d\n", x, y);
    return 0;
}
```

预期输出：`x=7, y=3`。

`const` 的两种常见写法：`void f(const int *p)` 不能通过 p 改内容（p 本身可以改指向）；`void g(int *const p)` 的 p 不能改指向（内容可以改）。读法：从右往左念——`const int *p` 是「p 是指针，指向 const int」。

常见错误：

- 函数里以为改了形参就改了外面：对非指针参数，改的是副本。
- 对 `const` 指针指向的内容赋值：编译器会直接报错，这是好事。
- 返回局部变量的地址（见下一节）。

### 2.5 栈与堆

```
高地址
  栈（stack）      局部变量；自动分配/回收；向下增长；大小有限（MB 级）
  ...（向下增长）
  堆（heap）       malloc 分配；手动 free；向上增长；可用到内存上限
  全局/静态变量    程序启动时分配，整个程序期间一直存在
  代码/只读数据    指令、"字符串字面量"
低地址
```

栈上内存随函数返回自动失效，所以**不能返回局部数组的地址**：

```c
#include <stdio.h>
static char *make_greeting_bad(void)
{
    char buf[16] = "hello";
    return buf;      /* 错误：buf 随函数结束失效 */
}
int main(void)
{
    char *s = make_greeting_bad();
    printf("%s\n", s);     /* 未定义行为：可能乱码、可能崩溃 */
    return 0;
}
```

正确做法：由调用者传入缓冲区，或用 `malloc` 分配后由调用者 `free`：

```c
#include <stdlib.h>
#include <string.h>

static char *make_greeting(void)
{
    char *buf = malloc(16);
    if (buf == NULL)
        return NULL;
    strncpy(buf, "hello", 15);
    buf[15] = '\0';
    return buf;                      /* 堆内存，函数返回后仍有效 */
}
```

常见错误：

- 返回局部变量地址；局部数组很大时还可能栈溢出（stack overflow）。
- 以为 `free` 会把内存清零：不会，内容可能还在，但不能再读。
- 把大数组放栈上（例如 `double a[1000000];` 8MB）导致崩溃；大缓冲区应 `malloc`。

### 2.6 动态内存：malloc / calloc / realloc / free

```c
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    int n = 0;
    printf("要读入几个整数? ");
    if (scanf("%d", &n) != 1 || n <= 0) {
        fprintf(stderr, "请输入正整数\n");
        return 1;
    }

    int *arr = malloc((size_t)n * sizeof(int));   /* 申请 n 个 int */
    if (arr == NULL) {                            /* 必须检查 */
        perror("malloc");
        return 1;
    }

    long long sum = 0;
    for (int i = 0; i < n; i++) {
        arr[i] = i * i;
        sum += arr[i];
    }
    printf("平方和 = %lld\n", sum);

    /* 扩容：多放一个元素。realloc 可能搬家，必须用新指针接住 */
    int *bigger = realloc(arr, (size_t)(n + 1) * sizeof(int));
    if (bigger == NULL) {
        free(arr);            /* 失败时原内存仍有效，先释放再退出 */
        perror("realloc");
        return 1;
    }
    arr = bigger;
    arr[n] = 0;
    printf("扩容后 arr[%d] = %d\n", n, arr[n]);

    free(arr);                /* 只释放一次 */
    arr = NULL;               /* 释放后置空，避免悬空指针 */
    return 0;
}
```

三种分配函数：`malloc(size)` 内容未初始化；`calloc(n, size)` 清零并检查乘法溢出（数组场景优先用）；`realloc(p, size)` 调整大小，可能搬到新地址，失败返回 `NULL` 且原块仍有效。

常见错误：

- 不检查返回值：内存不足时返回 `NULL`，直接写就崩溃。
- 直接写回原指针：`p = realloc(p, ...)` 一旦失败就丢了原地址，泄漏。
- 忘记 `free`（泄漏）；`free` 两次（double free）；`free` 栈上地址。
- 分配大小算错：`malloc(n)` 想装 int，少乘了 `sizeof(int)`。

### 2.7 五类常见内存错误

下面每段都是错误示范，要放进 `main`（或相应函数）里才能编译运行：

```c
/* 1. 未初始化：读的是垃圾值 */
int *p = malloc(sizeof(int) * 4);
printf("%d\n", p[0]);        /* 错：未初始化就读取（calloc 可以避免） */
free(p);
/* 2. 越界：写了不属于自己的字节 */
int a[4];
a[4] = 1;                    /* 错：合法下标是 0..3 */
/* 3. 内存泄漏：先丢了指针，再也没法 free */
char *s = malloc(100);
s = "hello";                 /* 错：原地址丢了，泄漏 100 字节 */
/* 4. 悬空指针（use-after-free） */
int *q = malloc(sizeof(int));
*q = 5;
free(q);
printf("%d\n", *q);          /* 错：已释放还读 */
/* 5. double free */
int *r = malloc(sizeof(int));
free(r);
free(r);                     /* 错：同一块内存释放两次 */
```

这些错误不一定马上崩溃，可能「今天正常、明天出错」，所以必须用工具检查。养成习惯：**谁分配，谁释放；释放后置 `NULL`；长度和分配大小用同一个变量表达。**

常见错误：

- 靠「运行没崩」判断没有内存问题：泄漏和越界常常潜伏。
- 在循环里反复 `malloc` 却不 `free`：长时间运行的程序内存持续增长。
- 结构体里嵌套指针只 `free` 了外层：内部指针也要单独释放（本项目暂时用不到，先记住）。

### 2.8 用 valgrind 与 ASan 检测

示例程序 `leak.c`：

```c
#include <stdlib.h>
int main(void)
{
    int *p = malloc(10 * sizeof(int));
    if (p == NULL)
        return 1;
    p[0] = 1;
    return 0;        /* 忘记 free(p) */
}
```

方法一：valgrind（不用重新编译，慢 10~50 倍）：

```bash
gcc -Wall -Wextra -g leak.c -o leak
valgrind --leak-check=full ./leak
```

输出关键片段：

```
total heap usage: 1 allocs, 0 frees, 40 bytes allocated
   definitely lost: 40 bytes in 1 blocks
```

方法二：AddressSanitizer（重新编译，快，能查越界、use-after-free、泄漏）：

```bash
gcc -Wall -Wextra -g -fsanitize=address,undefined leak.c -o leak_asan
./leak_asan
```

输出关键片段：

```
ERROR: LeakSanitizer: detected memory leaks
SUMMARY: AddressSanitizer: 40 byte(s) leaked in 1 allocation(s).
```

越界会被直接定位到行号（`ERROR: AddressSanitizer: stack-buffer-overflow ... #0 ... in main bad.c:7`）。建议：日常开发用 ASan，交付/验收时跑一遍 valgrind 看 `definitely lost` 是否为零；两者不要同时开。

常见错误：

- 只看到 `still reachable` 就以为泄漏：真正要关心的是 `definitely lost` 与 `indirectly lost`。
- 编译没加 `-g`：报错只有地址没有行号，定位困难。
- 用 ASan 版本测性能：结果没有参考价值。

### 2.9 与 Python 的对照

| 主题 | Python | C |
| --- | --- | --- |
| 变量 | 名字绑定到对象 | 变量是一块有类型的内存 |
| 引用 | 所有对象都是引用 | 指针需要显式声明与解引用 |
| 空值 | `None` | `NULL` |
| 列表 | 自动扩容、带边界检查 | 数组固定长度、不检查边界；扩容靠 `realloc` |
| 内存回收 | 引用计数 + GC | 手动 `free`，没有 GC |
| 悬空引用 | GC 保证对象存活 | `free` 之后指针悬空，再用是未定义行为 |
| 调试内存 | 基本不用管 | valgrind / ASan 是必备工具 |

核心差异：Python 里「变量」是贴在对象上的标签，C 里「变量」就是内存本身；生命周期在 Python 由 GC 看住，在 C 完全由你负责。

## 练习

1. 写函数 `int *find_min(int *a, int n)`，返回最小元素所在地址（不是下标）；在 `main` 里打印该值与该下标（用指针相减）。
   提示：先假设 `a[0]` 最小，遍历时用 `*p < *best` 比较。验收：对 `{3, 1, 4, 1, 5}` 输出最小值 1 与下标 1（第一个最小）。

2. 不用 `strdup`，自己实现 `char *my_strdup(const char *s)`：先 `strlen` 算长度，`malloc(len + 1)`，拷贝，返回；在 `main` 里打印后 `free`。
   提示：`malloc` 失败返回 `NULL`；拷贝完补 `'\0'`。验收：`valgrind --leak-check=full ./mydup` 显示 `definitely lost: 0 bytes`。

3. 动态数组统计：读入 `n`（正整数），`malloc` 一个 `double` 数组并读入 n 个数，输出平均值；然后 `realloc` 在末尾追加这个平均值并打印全部元素（保留两位小数）。
   提示：读入前检查 `scanf` 返回值；`realloc` 失败分支要 `free` 原数组。验收：输入 `3` 和 `1 2 3`，输出平均值 `2.00`，追加后打印 `1.00 2.00 3.00 2.00`。

4. 动态二维矩阵：用 `malloc` 创建 `m` 行 `n` 列整数矩阵（每行单独 `malloc`），填入 `a[i][j]=(i+1)*(j+1)`，打印，最后逐行 `free` 再释放行指针数组。
   提示：先读 `m,n`；分配 `int **a`；每个 `a[i]` 都要检查。验收：`gcc -fsanitize=address,undefined -g` 编译运行无报告。

5. 修 bug：把 2.7 节五段错误片段分别补成完整程序并故意运行一次（或用 ASan 编译），记录报错信息；然后把它们全部改成正确版本，让 ASan 与 valgrind 都没有输出。
   提示：第 1 段用 `calloc`；第 2 段把下标改回 0..3；第 3 段直接 `strncpy` 进已分配内存；第 4、5 段删除复用与重复释放。验收：五个正确程序 ASan 无 ERROR，valgrind 无 `definitely lost`。
