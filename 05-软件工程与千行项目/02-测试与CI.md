## 正文

### 2.1 fixture：测试的"公共准备"

fixture 是"被多个测试复用的准备代码"，通过参数名自动注入测试函数。

```python
# tests/conftest.py
"""pytest 会自动加载本文件；放在这里的 fixture 对整个 tests/ 目录可见。"""

import numpy as np
import pytest

from mypkg.spectrum import Spectrum


@pytest.fixture
def simple_spectrum() -> Spectrum:
    """一条可复现的测试光谱：常数底 + 一个高斯峰。"""
    x = np.linspace(0.0, 100.0, 1001)
    y = 10.0 + 50.0 * np.exp(-0.5 * ((x - 50.0) / 3.0) ** 2)
    return Spectrum(x, y, name="simple")
```

```python
# tests/test_spectrum.py
import pytest


def test_peak_intensity(simple_spectrum) -> None:
    # 峰值 = 底 10 + 峰 50 = 60，数值近似用 approx
    assert simple_spectrum.peak_intensity == pytest.approx(60.0, abs=0.5)
```

scope 决定 fixture 的执行次数：`function`（默认，每个测试一次）、`module`、`session`。
需要清理资源时用 `yield`：

```python
@pytest.fixture
def sqlite_db(tmp_path):
    import sqlite3

    conn = sqlite3.connect(tmp_path / "test.db")
    conn.execute("CREATE TABLE spectra (id INTEGER PRIMARY KEY, name TEXT)")
    yield conn
    conn.close()  # 测试之后执行，即使测试失败也会执行
```

**常见错误**

- fixture 里用随机数据且不固定种子，测试偶发失败；
- `scope="session"` 的 fixture 被测试修改，导致测试之间产生顺序依赖；
- 把业务逻辑搬进 `conftest.py`（它应该只有准备与清理）。

### 2.2 参数化：一份逻辑测多组输入

同一段逻辑用多组输入验证时，不要复制测试函数，用 `@pytest.mark.parametrize`：

```python
import pytest

from mypkg.parsing import parse_float


@pytest.mark.parametrize(
    ("raw", "expected"),
    [
        ("  3.14 ", 3.14),
        ("1e3", 1000.0),
        ("-2.5", -2.5),
        ("+0.5", 0.5),
    ],
    ids=["strip", "scientific", "negative", "plus-sign"],  # 报告里的用例名
)
def test_parse_float(raw: str, expected: float) -> None:
    assert parse_float(raw) == pytest.approx(expected)


@pytest.mark.parametrize("raw", ["", "abc", "1.2.3", "nan"])
def test_parse_float_rejects(raw: str) -> None:
    with pytest.raises(ValueError):
        parse_float(raw)
```

**常见错误**

- 参数列表里放可变对象（列表/字典），多个用例共享同一对象，互相污染；
- 用例太多太慢却不用标记：用 `@pytest.mark.slow` + `pytest -m "not slow"` 分层运行。

### 2.3 tmp_path 与文件相关测试

`tmp_path` 是每个测试独立的临时目录（`pathlib.Path`），测文件读写必须用它：

```python
def test_write_and_read_roundtrip(tmp_path) -> None:
    path = tmp_path / "spec.csv"
    path.write_text("wavelength,intensity\n1.0,2.0\n2.0,3.0\n", encoding="utf-8")

    df = read_spectrum_csv(path)

    assert list(df.columns) == ["wavelength", "intensity"]
    assert len(df) == 2
```

**常见错误**

- 把测试文件写到项目目录或用户目录（污染工作区，CI 上可能无权限）；
- 忘记 `encoding="utf-8"`：Windows 默认编码不是 UTF-8，中文会乱码；
- 假设"测试运行时当前目录是某处"：所有路径都从 `tmp_path` 或测试文件位置推导。

### 2.4 monkeypatch 与 mock：隔离外部世界

测试要快、要确定、要离线。凡是"外部世界"（环境变量、时间、网络、随机数）都应该被替换：

```python
def test_cache_dir_from_env(monkeypatch, tmp_path) -> None:
    monkeypatch.setenv("MYPKG_CACHE", str(tmp_path))   # 影响 os.environ
    assert get_cache_dir() == tmp_path


def test_retry_uses_fake_clock(monkeypatch) -> None:
    # 假时钟替代真的 sleep/等待，测试瞬间完成
    monkeypatch.setattr("mypkg.retry.time.time", lambda: 1000.0)
```

用标准库 `unittest.mock` 验证"协作对象被正确调用"：

```python
from unittest.mock import Mock


def test_pipeline_writes_expected_records() -> None:
    sink = Mock()                     # 假存储：只记录被调用了什么
    pipeline = Pipeline(source=FakeSource(), cleaner=Cleaner(), storage=sink)

    pipeline.run("dummy.csv")

    sink.write.assert_called_once()
    name, stats = sink.write.call_args.args
    assert name == "dummy.csv"
    assert stats["n_points"] == 3
```

原则：**只 mock 边界**（网络、子进程、时间、随机），不要把被测对象自己也 mock 掉。
`patch` 的路径要写"使用它的地方"，不是"定义它的地方"：
`@patch("mypkg.pipeline.requests.get")` 而不是 `@patch("requests.get")`。

**常见错误**

- mock 过度：测试只验证"某个 mock 被调用"，产品逻辑改坏了测试还全绿；
- patch 路径写错，测试默默 patch 了一个从未使用的名字（不会报错）；
- 随机数不固定种子：概率性失败的测试是最难查的 bug 之一。

### 2.5 pytest.approx：浮点数不能直接相等

`0.1 + 0.2 != 0.3` 是二进制浮点的常识，比较浮点必须用容差：

```python
import pytest


def test_float_with_tolerance() -> None:
    assert 0.1 + 0.2 == pytest.approx(0.3)           # 默认相对容差 1e-6
    assert 3.14159 == pytest.approx(3.14, abs=0.01)  # 绝对容差
```

数组用 `np.testing.assert_allclose(actual, expected, rtol=1e-6)`，
`pytest.approx` 也支持数组：`assert actual == pytest.approx([1, 2, 3])`。

**常见错误**

- 用 `==` 比较浮点/数组结果，偶发失败或永远失败；
- 容差拍脑袋：应根据数据精度决定 `abs`/`rtol`（流量精度 1e-3，就不要用 1e-9）；
- 对 NaN：显式用 `math.isnan` 或 `np.isnan` 判断，不要指望 `approx`。

### 2.6 测试组织与命名

```text
tests/
├── conftest.py          # 共享 fixture，不放业务逻辑
├── test_spectrum.py     # 与 src/mypkg/spectrum.py 对应
├── test_io.py
├── test_cli.py
└── data/                # 极小的测试样本（几 KB，进 Git）
```

约定：

- 文件 `test_*.py`，函数 `test_*`，类 `Test*`（类式测试本阶段可选，不必强求）；
- 一个测试只验证一件事；结构用"准备（given）→ 行动（when）→ 断言（then）"；
- 测试名说清行为：`test_crop_returns_new_object` 比 `test_crop_2` 强得多；
- 测试也是代码：重复的准备抽成 fixture，重复的断言抽成小 helper；
- 慢的集成测试单独标记：`@pytest.mark.integration` / `@pytest.mark.slow`。

**常见错误**

- 一个测试里断言十件事，失败时定位困难；
- 测试之间共享可变状态、依赖执行顺序（单独运行就失败）；
- 大量复制粘贴相似测试却不参数化。

### 2.7 覆盖率：数字的意义与局限

```bash
pytest --cov=myproject --cov-report=term-missing --cov-report=html
# term-missing：在终端列出未覆盖的行号
# html：生成 htmlcov/index.html，可逐文件查看
```

在 `pyproject.toml` 里固化配置：

```toml
[tool.coverage.run]
source = ["myproject"]
branch = true            # 同时统计分支覆盖

[tool.coverage.report]
exclude_lines = [
    "if __name__ == .__main__.:",
    "raise NotImplementedError",
]
```

理解：

- 行覆盖 = 这行执行过；分支覆盖 = 每个 if 的两条路都走过，后者更严格；
- 经验线：核心算法与数据校验 >= 80%，整体 60%~80% 是常见健康区间；
- 覆盖率高 != 测试好：没有断言的测试同样拉高覆盖率；
- 覆盖率是"找没测到的角落"的工具，不是 KPI。

**常见错误**

- 写一堆无断言的"占位测试"凑数字；
- 把 `.coverage`、`htmlcov/` 提交进 Git（应写进 `.gitignore`）；
- 为了覆盖率去测 `if __name__ == "__main__"` 或第三方库代码。

### 2.8 测试金字塔与什么值得测

**金字塔**：单元测试（多、快、便宜）→ 集成测试（中）→ 端到端测试（少、慢、脆弱）。
比例大概 70% / 20% / 10%，不要倒过来。

科研代码的测试优先级：

| 优先级 | 对象 | 例子 |
| --- | --- | --- |
| 最高 | 纯计算函数 | 归一化、插值、峰位查找、单位换算 |
| 高 | 解析与边界 | CSV/HDF5 解析、空文件、NaN、异常格式 |
| 中 | CLI 参数 | 子命令解析、默认值、错误退出码 |
| 中 | 数据库读写 | 往返一致性、重复写入的幂等性 |
| 低 | 端到端 | 用几 KB 的样本数据跑完整流程 |

值得测的边界：空数组、单元素、全 NaN、长度不匹配、极大/极小值、多个来源单位不一致。
值得写回归测试：曾经出现过 bug 的场景（先写一个能复现 bug 的失败测试，再修）。

**常见错误**

- 花大量时间测画图细节（应测"传给画图的数据"而不是像素）；
- 测试第三方库本身（pandas 不用你测）；
- 只测顺利路径，不测异常与边界——而 bug 几乎都在边界上。

### 2.9 GitHub Actions：让机器帮你跑测试

概念层级：**workflow**（`.github/workflows/*.yml`）→ **job** → **step**；
每次 push / PR 触发一个 **runner**（云端机器）执行工作流。

把下面这份配置复制到项目的 `.github/workflows/ci.yml`（与模板目录中的文件一致）：

```yaml
name: CI

on:
  push:
    branches: [main]
  pull_request:
    branches: [main]

jobs:
  test:
    runs-on: ubuntu-latest

    strategy:
      fail-fast: false        # 一个版本失败，其他版本继续跑完
      matrix:
        python-version: ["3.10", "3.11", "3.12"]

    steps:
      - name: 检出代码
        uses: actions/checkout@v4

      - name: 安装 Python ${{ matrix.python-version }}
        uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
          cache: pip            # 自动缓存 pip 下载，加速后续构建

      - name: 安装项目与开发依赖
        run: |
          python -m pip install --upgrade pip
          pip install -e ".[dev]"

      - name: 运行测试
        run: pytest --cov=myproject --cov-report=term-missing
```

逐段说明：

- `on:` 后面是触发条件；`pull_request:` 留空表示任何目标分支的 PR；
- `strategy.matrix` 让同一个 job 在 3 个 Python 版本上各跑一遍；
- `checkout` 把仓库代码拉到 runner 上；`setup-python` 装指定版本并缓存 pip；
- `run: |` 里的多行命令按 shell 逐行执行；
- 仓库设置里把默认分支保护好、要求 CI 通过才能合并，是之后的自然延伸。

README 里加状态徽章（把用户名/仓库名替换掉）：

```markdown
![CI](https://github.com/用户名/仓库名/actions/workflows/ci.yml/badge.svg)
```

**常见错误**

- YAML 缩进用 Tab 或层级错位（YAML 只认空格，建议 2 空格一级）；
- 矩阵里 `3.10` 不加引号会被 YAML 解析成数字 3.1，跑成 Python 3.1（不存在）；
- 忘记 `checkout`，job 里找不到代码；
- 本地能过 CI 不能过：本地装过依赖而 `pyproject.toml` 没写，或者测试写入固定路径；
- 工作流放在非默认分支上不会触发（`on.push` 只对匹配的分支生效）。

### 2.10 pre-commit 一句话

pre-commit 在 `git commit` 前自动运行一组检查（去掉行尾空格、格式化、跑 lint），
配置在 `.pre-commit-config.yaml`；本阶段知道概念即可，等代码风格问题开始困扰你时再引入。
官方文档：<https://pre-commit.com/>。

## 练习

1. **给 Spectrum 写测试**：正常数据、空数组、长度不一致抛 `ValueError`。
   提示：参数化 + `pytest.raises`。验收：`pytest -q` 全绿，至少 6 个用例。
2. **往返测试**：用 `tmp_path` 测"写入 CSV → 读回 → 数值一致"。
   提示：用 `pytest.approx` / `assert_allclose`。验收：不读固定路径、不联网，单独运行通过。
3. **隔离外部世界**：找一个读环境变量或发网络请求的函数，用 `monkeypatch` / `Mock` 测试。
   提示：只替换边界，给被测逻辑一个"假的对端"。验收：改环境变量后测试结果不变。
4. **覆盖率实战**：给 01 篇的小包配置 `[tool.coverage]` 并生成 HTML 报告。
   提示：跑 `--cov=包名 --cov-report=html`，打开 `htmlcov/index.html`。
   验收：指出 3 个未覆盖的行并说明是否值得补测试。
5. **CI 上云**：创建 GitHub 仓库并让 CI 在 3 个 Python 版本上变绿，把徽章加进 README。
   提示：先本地 `pytest` 全绿再 push。验收：Actions 页面 3 个矩阵任务全部通过。
